### 3. ⚙️ [Расширенные настройки и оптимизация](AMNEZIAWG_ADVANCED_CONFIGURATION.md)
**Для настройки обфускации и обхода блокировок**

Детальное руководство по параметрам:
- **Параметры обфускации**
  - Jc, Jmin, Jmax (junk packets)
  - S1, S2, S3, S4 (packet-specific junk)
  - H1, H2, H3, H4 (magic headers)
  - I1-I5 (special junk patterns)
- **Готовые сценарии настройки**
  1. Нет блокировок (максимальная скорость)
  2. Слабая/средняя блокировка (рекомендуется)
  3. Сильная блокировка (максимальная обфускация)
  4. Имитация HTTPS трафика
- **Продвинутые техники**
  - Смена порта на 443 для имитации HTTPS
  - Оптимизация MTU для вашей сети
  - Ротация параметров при адаптации DPI
  - Туннелирование через TCP (udp2raw)
- **Мониторинг и тестирование**
  - Проверка эффективности обфускации
  - Тестирование скорости
  - Анализ трафика через tcpdump/Wireshark

**Используйте это:** Когда нужно настроить обфускацию для обхода блокировок или оптимизировать производительность.

   - Настройка параметров для разных сценариев

3. Смените порт на 443

1. Прочитайте [Расширенные настройки](AMNEZIAWG_ADVANCED_CONFIGURATION.md) - раздел:
   - Сценарий "Нет блокировок"
2. Оптимизируйте MTU для вашей сети

### Нужно быстро добавить/удалить пользователя
Используйте [Быструю справку](AMNEZIAWG_QUICK_REFERENCE.md) - готовые скрипты для копирования.

## 🔑 Ключевые концепции

### Что такое AmneziaWG?
AmneziaWG - это обфусцированная версия WireGuard с механизмами обхода Deep Packet Inspection (DPI). Добавляет:
- Junk-данные к пакетам (изменяет размер)
- Magic headers (имитация других протоколов)
- Special patterns (маскировка под DNS/HTTPS)

### Основные параметры обфускации
- **Jc** (3-7): Количество junk-пакетов - влияет на overhead
- **S1** (15-150): Junk для init пакета - **КРИТИЧЕН** для обхода DPI!
- **S2** (15-150): Junk для response пакета - должен отличаться от S1
- **S4** (0-20): Junk для data пакетов - влияет на скорость, **не ставьте > 15**!
- **H1-H4**: Magic headers - случайные числа для имитации протоколов
- **I1**: DNS pattern - имитация DNS-запросов

### Рекомендации для обхода блокировок
1. **Порт 443** - имитирует HTTPS
2. **S1 ≠ S2** - разные размеры init/response пакетов
3. **Jc = 5-7** - для сильных блокировок
4. **S4 ≤ 15** - иначе сильное снижение скорости
5. **MTU = 1280-1420** - в зависимости от сети

### Влияние параметров на скорость
```
Jc=0, S4=0:     100% скорости (baseline)
Jc=3, S4=5:     ~95% скорости  ← рекомендуется
Jc=5, S4=10:    ~85% скорости
Jc=7, S4=15:    ~75% скорости
Jc=10, S4=20:   ~65% скорости  ← не рекомендуется
```

## 🆘 Решение типичных проблем

### Клиент не может подключиться
1. Проверьте, что параметры обфускации **ИДЕНТИЧНЫ** на сервере и клиенте
2. Убедитесь, что порт не заблокирован firewall
3. Попробуйте уменьшить S1, S2 до 50-70

### Низкая скорость
1. Уменьшите Jc, Jmax, S4
2. Оптимизируйте MTU (протестируйте разные значения)
3. Попробуйте MTU = 1280

### Периодические обрывы
1. Слишком большой S4 - уменьшите до 10
2. Слишком большой Jc - уменьшите до 3-4
3. Проблема с MTU - попробуйте 1280

### Блокировка после нескольких дней
1. DPI адаптировался - смените параметры обфускации
2. Смените порт на 443
3. Ротируйте параметры (скрипт в Быстрой справке)
