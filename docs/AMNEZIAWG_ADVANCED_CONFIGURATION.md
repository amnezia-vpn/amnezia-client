## Введение в параметры обфускации

AmneziaWG - это модифицированная версия WireGuard с добавленными механизмами обфускации для обхода систем Deep Packet Inspection (DPI). Обфускация работает путем:

1. **Добавления junk-данных** к пакетам WireGuard для изменения размера пакетов
2. **Использования magic headers** - случайных маркеров для имитации других протоколов
3. **Специальных junk-паттернов** для маскировки под легитимный трафик

### Принцип работы DPI-блокировок

Системы DPI определяют WireGuard по:
- Характерному размеру пакетов (148, 92, 60 байт)
- Паттернам хендшейка
- Постоянному размеру пакетов данных

AmneziaWG решает это добавлением случайных данных к каждому типу пакета.

## Основные параметры обфускации

### 1. Junk Packet Parameters (общие параметры мусорных данных)

#### **Jc** - Junk Packet Count
- **Описание**: Количество junk-пакетов, добавляемых к каждому пакету данных
- **Диапазон**: 0-10
- **По умолчанию**: 3-6 (случайно при установке)
- **Рекомендации**:
  - `0-2` - минимальная обфускация, максимальная скорость
  - `3-5` - баланс (рекомендуется)
  - `6-10` - максимальная обфускация, но снижение скорости

**Влияние**: Чем больше значение, тем сложнее DPI определить паттерн, но выше overhead.

#### **Jmin** - Junk Packet Minimum Size
- **Описание**: Минимальный размер каждого junk-пакета (байты)
- **Диапазон**: 5-100
- **По умолчанию**: 10
- **Рекомендации**: 10-20 для большинства случаев

#### **Jmax** - Junk Packet Maximum Size
- **Описание**: Максимальный размер каждого junk-пакета (байты)
- **Диапазон**: Jmin+1 до 1000
- **По умолчанию**: 30-50
- **Рекомендации**:
  - `30-50` - стандартная обфускация
  - `50-150` - усиленная обфускация
  - `150-1000` - максимальная обфускация (снижает скорость)

---

### 2. Specific Packet Junk Sizes (размеры для конкретных типов пакетов)

#### **S1** - Init Packet Junk Size
- **Описание**: Размер junk-данных для пакета инициализации хендшейка
- **Диапазон**: 15-150 байт
- **По умолчанию**: 15-150 (случайно)
- **Важность**: КРИТИЧНА! Пакет инициализации - главная сигнатура WireGuard

**Рекомендации по настройке**:
```
Слабая блокировка:  S1 = 20-40
Средняя блокировка: S1 = 50-100
Сильная блокировка: S1 = 100-150
```

#### **S2** - Response Packet Junk Size
- **Описание**: Размер junk-данных для пакета ответа на хендшейк
- **Диапазон**: 15-150 байт
- **По умолчанию**: 15-150 (случайно, отличается от S1)
- **Важность**: ВЫСОКАЯ

**Примечание**: S1 и S2 должны генерировать РАЗНЫЕ итоговые размеры пакетов:
```
Размер Init пакета = 148 + S1
Размер Response пакета = 92 + S2
```
Если `148 + S1 == 92 + S2`, WireGuard может быть обнаружен по одинаковым размерам.

#### **S3** - Cookie Reply Packet Junk Size
- **Описание**: Размер junk-данных для cookie reply пакета
- **Диапазон**: 0-64 байт
- **По умолчанию**: 0-64 (случайно)
- **Важность**: СРЕДНЯЯ

#### **S4** - Transport Packet Junk Size
- **Описание**: Размер junk-данных для каждого транспортного (data) пакета
- **Диапазон**: 0-20 байт
- **По умолчанию**: 0-20 (случайно)
- **Важность**: СРЕДНЯЯ

**ВНИМАНИЕ**: Большое значение S4 сильно снижает скорость, так как применяется к КАЖДОМУ пакету данных!

---

### 3. Magic Headers (магические заголовки)

Magic headers - это случайные числовые последовательности, добавляемые к пакетам для имитации других протоколов.

#### **H1** - Init Packet Magic Header
- **Формат**: `начало-конец` (например, `1234567-9876543`)
- **По умолчанию**: Случайная пара чисел
- **Важность**: ВЫСОКАЯ

#### **H2** - Response Packet Magic Header
#### **H3** - Underload Packet Magic Header  
#### **H4** - Transport Packet Magic Header

**Правила генерации**:
```
H1 = random1_min - random1_max
H2 = random2_min - random2_max (random2_min > random1_max)
H3 = random3_min - random3_max (random3_min > random2_max)
H4 = random4_min - random4_max (random4_min > random3_max)
```

**Пример правильных значений**:
```
H1 = 5-1234567
H2 = 1234568-5678901
H3 = 5678902-9876543
H4 = 9876544-2147483647
```

---

### 4. Special Junk Patterns (специальные junk-паттерны)

#### **I1, I2, I3, I4, I5** - Special Junk 1-5
- **Описание**: Специальные hex-паттерны для имитации DNS-трафика или других протоколов
- **По умолчанию**: 
  - I1: DNS query паттерн (имитация DNS-запроса)
  - I2-I5: пустые
- **Формат**: Hex-строка в формате `<b 0x....>`

**Пример I1 (имитация DNS)**:
```
I1 = <b 0x084481800001000300000000077469636b65747306776964676574096b696e6f706f69736b0272750000010001c00c0005000100000039001806776964676574077469636b6574730679616e646578c025c0390005000100000039002b1765787465726e616c2d7469636b6574732d776964676574066166697368610679616e646578036e657400c05d000100010000001c000457fafe25>
```

Это hex-представление DNS-запроса к `tickets.widget.kinopoisk.ru`, что делает трафик похожим на обычный DNS.

**Использование**:
- Оставьте I1 со значением по умолчанию для имитации DNS
- I2-I5 можно использовать для других паттернов (требует глубоких знаний)

## Изменение порта сервера

### Зачем менять порт?

Стандартный порт WireGuard (51820) легко блокируется. Рекомендуемые порты:

1. **443** (HTTPS) - наиболее эффективен для обхода блокировок
2. **53** (DNS) - также эффективен, но требует root на клиенте
3. **80** (HTTP) - работает, но менее безопасен
4. **8080, 8443** - альтернативные веб-порты
5. **Случайный высокий порт** (49152-65535)

### Как изменить порт на существующем сервере

```bash
# 1. Подключиться к серверу
ssh root@ваш-сервер

# 2. Остановить контейнер
docker stop amnezia-awg

# 3. Создать backup
docker cp amnezia-awg:/opt/amnezia/awg /tmp/awg-backup

# 4. Удалить старый контейнер
docker rm amnezia-awg

# 5. Создать новый контейнер с новым портом (например, 443)
# ВНИМАНИЕ: Нужно знать образ контейнера. Узнать можно:
docker images | grep awg

# Пересоздать контейнер с новым портом (пример для порта 443):
docker run -d \
  --privileged \
  --log-driver none \
  --restart always \
  --cap-add=NET_ADMIN \
  --cap-add=NET_RAW \
  --cap-add=SYS_MODULE \
  -v /lib/modules:/lib/modules \
  -p 443:51820/udp \
  --name amnezia-awg \
  --sysctl net.ipv4.conf.all.src_valid_mark=1 \
  amnezia-awg

# 6. Восстановить данные
docker cp /tmp/awg-backup amnezia-awg:/opt/amnezia/awg

# 7. Войти в контейнер и изменить конфигурацию
docker exec -it amnezia-awg bash

# 8. Отредактировать порт в конфигурации (опционально, если хотите изменить и внутри)
vi /opt/amnezia/awg/awg0.conf
# Найти строку: ListenPort = 51820
# Оставить как есть или изменить

# 9. Перезапустить интерфейс
awg-quick down awg0
awg-quick up awg0

exit

# 10. Проверить, что порт слушается
netstat -tuln | grep 443
```

**В конфигурациях клиентов** нужно изменить:
```ini
[Peer]
Endpoint = ваш-сервер:443  # Вместо :51820
```

## Оптимизация MTU

MTU (Maximum Transmission Unit) - максимальный размер пакета. Правильная настройка MTU критична для:
- Избежания фрагментации пакетов
- Максимальной скорости
- Стабильности соединения

### Как определить оптимальный MTU

```bash
# На клиенте (Linux/Mac):
ping -M do -s 1472 ваш-сервер-ip

# Если проходит - увеличивайте на 10:
ping -M do -s 1482 ваш-сервер-ip

# Если не проходит - уменьшайте на 10:
ping -M do -s 1462 ваш-сервер-ip

# Найдите максимальный размер, который проходит
# MTU для AmneziaWG = найденный_размер + 28
```

### Рекомендуемые значения MTU

```
Обычная сеть (Ethernet):     MTU = 1420
PPPoE (DSL):                 MTU = 1392
Мобильные сети:              MTU = 1280-1360
За NAT/VPN:                  MTU = 1280
Проблемная сеть:             MTU = 1280
```

### Как изменить MTU на сервере

```bash
docker exec -it amnezia-awg bash

# Редактировать конфигурацию
vi /opt/amnezia/awg/awg0.conf

# В секции [Interface] добавить или изменить:
# MTU = 1420

# Перезапустить интерфейс
awg-quick down awg0
awg-quick up awg0
```

### Как изменить MTU на клиенте

В конфигурационном файле клиента:
```ini
[Interface]
MTU = 1420
# ... остальные параметры ...
```

## Продвинутые техники обхода DPI

### 1. Комбинирование порта 443 + имитация HTTPS

```bash
# На сервере:
docker exec -it amnezia-awg bash

vi /opt/amnezia/awg/awg0.conf
```

Конфигурация:
```ini
[Interface]
# ... стандартные параметры ...
ListenPort = 443  # Если маппинг 443:443
Jc = 6
Jmin = 50
Jmax = 200
S1 = 120
S2 = 110
S3 = 50
S4 = 15
H1 = 443-10000
H2 = 10001-100000
H3 = 100001-1000000
H4 = 1000001-2147483647
```

### 2. Использование TCP вместо UDP (требует дополнительной настройки)

Некоторые DPI блокируют UDP на нестандартных портах. Можно туннелировать AmneziaWG через TCP:

**Вариант A: Использовать udp2raw**
```bash
# На сервере установить udp2raw
git clone https://github.com/wangyu-/udp2raw.git
cd udp2raw
make
./udp2raw -s -l 0.0.0.0:443 -r 127.0.0.1:51820 -k password --raw-mode faketcp

# AmneziaWG слушает на 51820
# udp2raw конвертирует TCP на 443 в UDP на 51820
```

### 3. Ротация параметров обфускации

Если блокировка адаптируется, периодически меняйте параметры:

```bash
# Скрипт для генерации новых параметров
docker exec -it amnezia-awg bash

cat > /tmp/rotate_params.sh << 'EOF'
#!/bin/bash

# Генерация новых значений
JC=$((RANDOM % 5 + 3))
JMIN=$((RANDOM % 20 + 10))
JMAX=$((RANDOM % 100 + 50))
S1=$((RANDOM % 135 + 15))
S2=$((RANDOM % 135 + 15))
S3=$((RANDOM % 64))
S4=$((RANDOM % 20))

# Генерация Magic Headers
H1_MIN=$((RANDOM % 1000 + 1))
H1_MAX=$((RANDOM % 10000000 + H1_MIN))
H2_MIN=$((H1_MAX + 1))
H2_MAX=$((RANDOM % 50000000 + H2_MIN))
H3_MIN=$((H2_MAX + 1))
H3_MAX=$((RANDOM % 500000000 + H3_MIN))
H4_MIN=$((H3_MAX + 1))
H4_MAX=2147483647

echo "Новые параметры:"
echo "Jc = $JC"
echo "Jmin = $JMIN"
echo "Jmax = $JMAX"
echo "S1 = $S1"
echo "S2 = $S2"
echo "S3 = $S3"
echo "S4 = $S4"
echo "H1 = $H1_MIN-$H1_MAX"
echo "H2 = $H2_MIN-$H2_MAX"
echo "H3 = $H3_MIN-$H3_MAX"
echo "H4 = $H4_MIN-$H4_MAX"

# Применить к конфигурации
sed -i "s/^Jc =.*/Jc = $JC/" /opt/amnezia/awg/awg0.conf
sed -i "s/^Jmin =.*/Jmin = $JMIN/" /opt/amnezia/awg/awg0.conf
sed -i "s/^Jmax =.*/Jmax = $JMAX/" /opt/amnezia/awg/awg0.conf
sed -i "s/^S1 =.*/S1 = $S1/" /opt/amnezia/awg/awg0.conf
sed -i "s/^S2 =.*/S2 = $S2/" /opt/amnezia/awg/awg0.conf
sed -i "s/^S3 =.*/S3 = $S3/" /opt/amnezia/awg/awg0.conf
sed -i "s/^S4 =.*/S4 = $S4/" /opt/amnezia/awg/awg0.conf
sed -i "s/^H1 =.*/H1 = $H1_MIN-$H1_MAX/" /opt/amnezia/awg/awg0.conf
sed -i "s/^H2 =.*/H2 = $H2_MIN-$H2_MAX/" /opt/amnezia/awg/awg0.conf
sed -i "s/^H3 =.*/H3 = $H3_MIN-$H3_MAX/" /opt/amnezia/awg/awg0.conf
sed -i "s/^H4 =.*/H4 = $H4_MIN-$H4_MAX/" /opt/amnezia/awg/awg0.conf

echo "Параметры обновлены!"
EOF

chmod +x /tmp/rotate_params.sh
/tmp/rotate_params.sh

# Применить изменения
awg syncconf awg0 <(awg-quick strip /opt/amnezia/awg/awg0.conf)
```

**ВАЖНО**: После ротации параметров НУЖНО обновить конфигурации ВСЕХ клиентов!

## Типичные проблемы и решения

### Проблема 1: Периодические обрывы соединения

**Причина**: Слишком большой S4 или Jc

**Решение**:
```bash
# Уменьшить S4 до 5-10
# Уменьшить Jc до 3-4
```

### Проблема 2: Низкая скорость

**Причины и решения**:
1. Слишком большие junk-параметры
   - Уменьшите Jc, Jmax, S4
   
2. Неправильный MTU
   - Проведите тест MTU (см. выше)
   - Попробуйте MTU = 1280
   
3. Перегруженный сервер
   - Проверьте `docker stats amnezia-awg`
   - Рассмотрите переход на более мощный сервер

### Проблема 3: Не удается подключиться после изменения параметров

**Причина**: Несоответствие параметров между сервером и клиентом

**Решение**:
```bash
# 1. Убедитесь, что параметры ИДЕНТИЧНЫ на сервере и клиенте
docker exec amnezia-awg grep -E "^(Jc|Jmin|Jmax|S1|S2|S3|S4|H1|H2|H3|H4)" /opt/amnezia/awg/awg0.conf

# 2. Скопируйте эти значения в конфигурацию клиента

# 3. Перезапустите клиент
```

### Проблема 4: Блокировка после нескольких дней работы

**Причина**: DPI система адаптировалась к вашим параметрам

**Решение**:
1. Смените порт сервера
2. Ротируйте параметры обфускации (скрипт выше)
3. Рассмотрите дополнительную обфускацию (udp2raw)

### Проблема 5: Клиент показывает "Handshake did not complete"

**Причины**:
1. Неправильные magic headers
2. S1 или S2 слишком большие
3. Firewall блокирует порт

**Решение**:
```bash
# 1. Проверить firewall
iptables -L -n -v | grep <порт>

# 2. Уменьшить S1 и S2 до 50-70
docker exec -it amnezia-awg bash
vi /opt/amnezia/awg/awg0.conf
# Изменить S1 и S2
awg syncconf awg0 <(awg-quick strip /opt/amnezia/awg/awg0.conf)

# 3. Проверить, что magic headers корректны
```

## Рекомендации по безопасности

1. **Регулярно меняйте параметры** - раз в 1-2 месяца
2. **Используйте сильные PresharedKeys** - для всех клиентов
3. **Мониторьте логи** - проверяйте необычную активность
4. **Backup конфигураций** - перед каждым изменением
5. **Тестируйте в непиковое время** - чтобы не нарушать работу пользователей
6. **Документируйте изменения** - ведите журнал настроек

## Чек-лист оптимизации для максимальной устойчивости

- [ ] Порт изменен на 443 или 53
- [ ] Jc = 5-7
- [ ] Jmin = 20-30, Jmax = 100-150
- [ ] S1 = 100-145 (высокое значение)
- [ ] S2 = 100-145 (отличается от S1)
- [ ] S3 = 40-60
- [ ] S4 = 10-15 (не выше!)
- [ ] Magic headers настроены с большими диапазонами
- [ ] I1 использует DNS-паттерн
- [ ] MTU оптимизирован для вашей сети
- [ ] Все клиенты используют одинаковые параметры
- [ ] Конфигурации сохранены в backup
- [ ] Протестирована скорость и стабильность
